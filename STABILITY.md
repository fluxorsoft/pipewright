# Stability

Pipewright follows [semantic versioning](https://semver.org/) from 1.0.0. This page says what that promise covers.

## The stable surface

A change that breaks any of these needs a new major version (2.0):

| Surface | What is covered |
|---|---|
| Use case and environment YAML | Every key in the `pipewright/v1` schemas (`config/schemas/*.schema.json`), its meaning and its default |
| Environment manifest | The fields Pipewright reads (`pipewright/v1`); unknown fields are ignored with a warning, never an error |
| Release contract | Contract version 3: its fields and their meaning; contracts are write-once |
| CLI | Command names, flags, their meaning and exit codes (0 success, 1 a check failed, 2 a configuration error) |
| Lifecycle events | Event types and their fields, on Pub/Sub and in structured logs |
| Plugin API | `register(subparsers, common)` for the `pipewright.commands` entry point group (plugin API v1) |
| Component runtime | The documented functions of `pipewright_runtime` (`read_source`, `write_table`, `log`, `emit_event`, `ray_cluster`, `ray_job`) |

## Not covered

These may change in any release:

- Python modules and functions not listed above (`pipewright.*` internals).
- Wording of messages, warnings and generated documents (messages are written for people, not for parsing).
- The contents of files generated by `pipewright ci init` or `pipewright new-usecase`: regenerate them with
  `--force` after an upgrade.
- Anything marked preview or experimental in the documentation.

## How changes arrive

- **Minor versions (1.x)** add keys, commands, events and fields. Existing configuration keeps working unchanged.
- **Patch versions (1.x.y)** fix bugs and security issues only.
- **Deprecations:** anything on the stable surface that is going away first warns (in `validate`, `doctor` and the
  command's output) for at least one minor version, with the replacement named, before a major version removes it.
- **Upgrades are per environment:** a platform runs one launcher version per environment, pinned by digest; app
  teams pin the CLI version in CI. A newer manifest can require a minimum CLI version with `requires`.
